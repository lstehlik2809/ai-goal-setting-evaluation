# Recorded goal text across three years

A local Python pipeline for comparing employee goal-setting snapshots from 2023, 2024 and 2025. It measures recorded language and four separate textual qualities, then compares years using equal employee weights. An employee-cluster Bayesian bootstrap adds conditional credible intervals and directional probabilities. It also proposes goal-setting agent changes as hypotheses to test.

**The checked-in data are entirely synthetic. The demo scorer produces fabricated probabilities, not Clef judgments.** There are no company records, employee attributes or trained weights in this repository.

**Causal effects of AI are not identified.** Company-wide AI availability in 2025 coincides with calendar year. Business conditions, workforce composition, processes and exports may also change. Repeat-employee comparisons do not remove these confounders, and availability does not establish actual AI use. Human validation is outside this phase: domain accuracy, calibration and comparability across years remain unverified.

## Run the synthetic example

Python 3.10 or newer is required. Initial dependency acquisition needs an internet connection or an offline wheelhouse. After installation, the demo, language detection, syllable lookup, analysis and HTML report need no network access.

Windows PowerShell, from the repository root:

```powershell
. .\scripts\Set-ProjectEnvironment.ps1 | Out-Null
py -3.10 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e ".[test]"
.\.venv\Scripts\python.exe -m goal_eval run --config examples/synthetic/demo.yaml
```

Keep the checkout on **D:**. Run `Set-ProjectEnvironment.ps1` in each new PowerShell terminal **before** creating the virtual environment, installing packages, building, or running tests. It redirects process-local download caches and temporary files to D: and rejects C: storage before those operations. Existing Python/PowerShell executables may be on C:; the new `.venv`, dependencies, downloads and project files stay on D:. It makes no permanent environment or global software changes. See the [Windows local Clef guide](docs/windows-local-clef.md) for the pinned portable model runtime and optional separate D: storage root.

Linux/macOS:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -e '.[test]'
.venv/bin/python -m goal_eval run --config examples/synthetic/demo.yaml
```

Open `outputs/synthetic/report.html` in any browser. It is a single offline HTML file with inline SVG, accessible tables and no external fonts, scripts or assets. Full detail tables expand on demand. The root `manifest.json` identifies the current run and the `runs/<run_id>/` directory containing CSV/Parquet exports. Only a current successful run has a report at the root. Treat private scored exports and the cache as sensitive: they contain goal text or derived scores.

For a preview before installation, download and open the [checked-in synthetic report](examples/synthetic/report.html). The same folder includes [sample scored CSV](examples/synthetic/scored.csv), annual/paired/coverage summaries and a sanitized [example manifest](examples/synthetic/manifest.json). These are a fixed fabricated demonstration; rerun the pipeline to generate current outputs after changing inputs or configuration. Parquet exports are generated by the runnable workflow.

The installed `goal-eval` command is equivalent to `python -m goal_eval`. With this virtual environment, use `.venv\Scripts\goal-eval.exe` on Windows or `.venv/bin/goal-eval` on Linux. Run from any directory by supplying an absolute config path; all input, cache and output paths resolve relative to that config file.

Repeat the same run to reuse committed cache successes and regenerate a fresh consistent set of exports. Repeated source records remain separate observations; rescoring identical text does not give it an extra analysis weight or remove its existing weight.

With a complete scoring cache, the same `run` command also regenerates the Bayesian tables and report with the HTTP Clef server **off**: cache hits require no new model calls. A cache miss attempts the configured real backend and fails if that server is unavailable; there is no demo fallback. Changed text, rubric, backend identity or scoring settings may require the real server again. Bayesian-only settings do not change scoring-cache identity.

## Bayesian comparisons

Bayesian inference is enabled by default: 4,000 independent posterior draws, 95% equal-tailed credible intervals, seed 2026 (inherited from the run seed unless overridden), and batches of 64 draws. The default nine metrics are the four textual qualities, combined words per goal, combined Flesch Reading Ease and Flesch–Kincaid grade, and timing/strategy `present` probabilities. The primary report compares 2025 minus 2024 for all metric-valid annual employees and for employees valid in both years. Historical 2024 minus 2023 and common-three-year complete-case results remain available in expandable tables. Every cohort has explicit employee counts.

Optional configuration:

```yaml
bayesian:
  enabled: true
  draws: 4000
  credible_mass: 0.95
  seed: 2026
  draw_batch_size: 64
  # Optional subset; omit to use all nine defaults.
  metrics: [clarity, specificity, assessability, coherence, combined_words,
            combined_flesch_ease, combined_fk_grade, timing_present, strategy_present]
  practical_thresholds: {}  # Optional selected-metric -> positive native-unit threshold.
```

Set `bayesian.enabled: false` to retain only descriptive comparisons. A credible interval describes uncertainty in a conditional population mean change under the model; it is not the spread of individual goals. `P(change > 0)` is a posterior Monte Carlo estimate, distinct from the Clef probabilities for rubric options. Draw counts, positive-draw counts and Monte Carlo standard errors are exported. A value of zero or one from finite draws does not prove an alternative is impossible. Increases in length, readability or flags are not automatically improvements.

The model treats joint employee trajectories, including observation/eligibility patterns, as exchangeable and conditions on fixed, unvalidated scores and selected groups. If the records form a complete census, recorded means are already known; these intervals express conditional generalization, not uncertainty about those fixed means. They exclude human-rating, calibration, cross-year measurement error, shared manager effects and company-year shocks. They do not identify an AI causal effect. Positive practical thresholds, when supplied, use native metric units and express the user's judgment; no meaningful cutoff is supplied by default. See [the model and its limitations](docs/methods.md#bayesian-employee-cluster-bootstrap).

Regenerate the checked-in 120-employee sample with:

```powershell
.\.venv\Scripts\python.exe -m goal_eval generate-synthetic --output examples/synthetic --employees 120 --seed 2026
```

The generator is deterministic. It varies observation sets and goals per employee, includes performance/development goals, repeated templates, missing and blank descriptions, non-English and short ambiguous text. These are software exercises, not simulated treatment effects. The seed is recorded in the run manifest; changing it in a run config does not regenerate existing CSVs.

## Use private snapshots and a real local model

Copy [examples/real-config.example.yaml](examples/real-config.example.yaml) into an external private directory. Change its mappings, paths and immutable model revision. Keep company inputs, cache, outputs and weights outside this checkout; editable/source installations enforce that boundary. In an installed wheel there may be no associated checkout to detect, so the external-directory requirement remains an operator responsibility. Omit the description mapping if the export has none. Do not change `synthetic` to true for company data.

One original CSV snapshot per configured year is required. Required mappings are `employee_id` and `title`; `description` is optional. Encoding defaults to `utf-8-sig`, delimiter to comma. Both are configurable per input. IDs remain strings, including leading zeros and literal `NA`. Year comes from the file mapping, never from dates inside a goal. Input SHA-256 fingerprints and one-based source record numbers produce stable record IDs. Inputs are read without modification and rechecked before success.

The default missing marker is the literal `\N`. An empty cell is a blank string; whitespace-only text is distinct; an absent trailing cell, unmapped description or explicit missing marker is missing. CSV cannot recover distinctions that the source exporter discarded. Literal `NA`, `N/A`, `null` and `0` remain text unless you explicitly configure them as missing markers. Scored CSV uses empty cells for numeric missing values and raw missing strings; accompanying `*_state` columns preserve the original distinction. Parquet retains string nulls and empty strings directly. With pandas, read CSV IDs with `dtype={"employee_id": str}` and `keep_default_na=False`; use the state columns to reconstruct missing text.

### Loopback SystemOne HTTP

The HTTP adapter sends real SystemOne requests to an already running local Clef server at `http://127.0.0.1:30000/v1/systemone`. It disables environment proxies, accepts only loopback HTTP endpoints and rejects redirects. It validates returned model ID, all questions, options and probabilities; failures never fall back to the demo. `revision` pins the operator-declared local release and participates in the cache identity. The SystemOne response echoes a model name; it does **not** cryptographically verify the server's weights. Verify the server release and runtime separately, and record the exact server configuration before a real run. HTTP `inference` settings describe operator-applied server settings; the client does not configure the server.

[Cloudflare's Clef-Flash release](https://huggingface.co/Cloudflare/clef-flash) provides a 9B backbone and joint schema head under Apache-2.0. Its documented reference uses PyTorch 2.11 and Transformers 5.10.2 on an H200. These large optional dependencies and the weights are deliberately not installed by this package. Acquire and pin a complete trusted release separately; follow the release's runtime/serving instructions, bind to loopback and avoid automatic model acquisition during analysis. A hosted endpoint is unsupported because inference must stay local.

For a portable Windows alternative, the [D:-only setup/start scripts](docs/windows-local-clef.md) pin llama.cpp b11669 and the `ggml-org/Clef-Flash-GGUF` Q4_K_M release. This route uses a quantized model and does not require PyTorch, Docker, WSL, new drivers or a global runtime installation. CPU remains the script default; on the tested GTX 1660 Ti 6 GB machine, use the [Vulkan HTTP config](examples/synthetic/clef-vulkan-http.yaml) with 20 GPU layers. Two complete rubric requests returned valid local probabilities in 5.75 and 4.28 seconds. The [CPU HTTP config](examples/synthetic/clef-cpu-http.yaml) also succeeded on the same two requests, taking 52.16 and 48.84 seconds with still tighter memory headroom. These were bounded execution checks, not full-run throughput benchmarks or rating validation. Close other applications and measure headroom before larger jobs. Both use fabricated records and never fall back to demo scoring.

### Optional direct Python release adapter

An alternative uses the release's `load_release_model(path, device=..., dtype=..., local_files_only=True)` and `systemone(model, processor, request, max_length=...)`. Add these fields to a private config:

```yaml
backend:
  kind: direct
  model: Cloudflare/clef-flash
  revision: REPLACE_WITH_IMMUTABLE_RELEASE_REVISION
  model_path: /absolute/private/weights/clef-flash
  source_sha256: REPLACE_WITH_SHA256_OF_joint_schema_model.py
  device: cpu
  dtype: float32
  retries: 0
  inference: {max_length: 16384}
```

On Windows use a quoted forward-slash path such as `D:/private/weights/clef-flash`. Compute the trusted local source hash with `Get-FileHash -Algorithm SHA256 ...` (use lowercase in config) or `sha256sum ...`. The adapter checks required files and the Python source hash before import, forces Hugging Face/Transformers offline mode and never calls `snapshot_download`. Loading a release runs its Python code: verify that code and its dependencies before using it. The source hash is not a hash of all weight shards; the release revision remains operator-declared. All model/runtime settings are recorded in the manifest and cache identity.

CPU operation is an available **configuration path, not verified feasibility**. Nine billion float32 parameters alone require approximately 36 GB before the head, activations, tokenizer and runtime overhead; bfloat16 parameters alone are about 18 GB. Context length and batches increase memory. Actual compatibility, RAM/VRAM fit, throughput and any quantization route require a bounded pilot on the intended computer. No WSL, Docker, GPU or quantized runtime is assumed. The adapter uses one SystemOne request at a time; `batch_size` bounds durable cache commits, while `chunk_size` bounds ingestion/scored-export buffers. It is not GPU tensor batching. Aggregation currently loads projected numeric fields and IDs into memory. The potential 1.2 million records have not been performance-tested; use a pilot and adjust hardware/implementation before a full run.

**Current verification status:** actual local Q4_K_M Clef execution succeeded on this computer using Vulkan and CPU, with two full rubric requests per route and probability validation on all six questions. This establishes bounded runtime feasibility for those pinned quantized routes; CPU was much slower and had less available RAM. Original full-precision Python loading and large-run feasibility remain unverified. Fixture servers and the tiny fake local release in tests establish protocol behavior only; domain accuracy, calibration and cross-year comparability remain unverified for every route. See the [bounded probe details](docs/windows-local-clef.md#observed-bounded-probe-2026-10-23) and [methods](docs/methods.md).

The reviewed Vulkan launcher and full synthetic pipeline also passed together: 823 records completed in 70.38 seconds with 14 new native requests, 581 cache hits and zero inference failures; CSV, Parquet and HTML outputs were verified. The sample repeats many templates, so this is an integration result, not a throughput benchmark for unique goals or a basis for mass-run extrapolation. See [integration details](docs/windows-local-clef.md#complete-synthetic-workflow-integration).

## Outputs and recovery

Each run writes into a new `runs/<run_id>/` directory. `manifest.json` at the configured output root is authoritative. Status becomes `running` before input/backend validation and `failed` on handled errors or interruption; the root report is suppressed. A hard process kill can leave `running`, which is explicitly incomplete, while previously committed cache successes survive. Rerun the command after correcting the error. Previous run directories are historical artifacts and do not establish current success. Do not run simultaneous writers with the same output/cache configuration.

A small ignored `.CONFIG_NAME.goal-eval-state.json` beside a writable config remembers its output location so a later malformed/deleted config can still invalidate the previous success. It contains local paths only; keep it private. The manifest reports whether that locator was persisted. With a read-only config directory and unreadable configuration, a custom prior output location cannot be discovered; check the previous manifest directly.

SQLite stores successful validated probability distributions only, keyed by exact text, rubric hash/version, backend, declared model revision, runtime/inference settings and adapter version. Missing/failed inference is never zero and never stored as success. Failures are retried according to `backend.retries`, remain visible by record and make the run fail. Cache commits occur at bounded call batches and chunk completion. A new run rewrites exports rather than appending them.

Outputs include `scored.csv`, `scored.parquet`, employee-year means, annual means and contrasts, paired details/summaries, common-three-year trajectories, coverage, employee overlap, goal counts, goal-score distributions, sensitivities, `bayesian_annual.csv` and `bayesian_contrasts.csv`. [The data dictionary](docs/data-dictionary.md) defines their fields. The HTML excludes raw text and employee IDs; CSV/Parquet and caches are private. Console output includes aggregate progress only, and model exceptions are reduced to safe error categories.

The manifest records inputs/fingerprints, resolved config and hash, rubric hash/version, backend/revision, Python/dependency/runtime versions, source hash and Git revision when available, seed, coverage, failures, cache calls/hits, timings and completion status. Its `bayesian` block records model version, effective settings and hash, RNG/seed, employee-cluster unit, status, assumptions and elapsed time. Config paths and local manifests can themselves be sensitive. Keep them private. The synthetic HTML may be shared after checking it; it contains run/model metadata but no private goal text or IDs.
